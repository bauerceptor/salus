### Root Cause Analysis: INCONSISTENCY

The fundamental problem is **INCONSISTENCY** across the codebase:

1. **Data Types Misused**
   - `day_of_week` stored as integer but sometimes used as string ("monday")
   - Time stored as string "HH:MM" instead of proper Time type
   - Numeric readings stored as strings

2. **Route/Path Naming Inconsistent**
   - Patient uses: `patient_treatment_request_path(id: request.id, locale: I18n.locale)`
   - Specialist uses: different patterns
   - Tests use different helpers than what routes actually generate

3. **Factory Associations Mismatch**
   - Factory uses `specialist { nil }` but model `belongs_to :specialist`
   - Factory uses `patient:` but model uses `belongs_to :account`

4. **Controller Params Don't Match Model**
   - Controller permits `:specialization, :specialization_description, :field_of_expertise`
   - Model has no such fields

5. **View Uses Wrong Objects**
   - View calls `@specialist_user.full_name`
   - But `User` doesn't have `full_name` - `Account` does

## UNIFIED STANDARDS & SINGLE CRUD PATTERN (Single Source of Truth)

### Core Philosophy
Rails conventions exist for a reason. Follow ONE pattern everywhere:
- **Single naming convention** for routes, paths, params, variables
- **Single data type** for each kind of data (NOT strings for everything)
- **Single structure** for controllers, models, views, tests

### 1. DATABASE & MODELS

#### Table Naming (Plural, snake_case)
```ruby
# CORRECT
create_table :treatment_requests
create_table :specialist_schedules

# WRONG - never singular, never camelCase
create_table :TreatmentRequest
create_table :specialistRequests
```

#### Primary Keys
```ruby
# ALWAYS UUID with gen_random_uuid()
create_table :model_name, id: :uuid, default: -> { "gen_random_uuid()" }
```

#### Foreign Keys
```ruby
# ALWAYS use references with type: :uuid
t.references :specialist, null: false, foreign_key: true, type: :uuid
t.references :account, null: false, foreign_key: true, type: :uuid
```

#### Data Types - USE THE RIGHT TYPE
```ruby
# CORRECT - proper data types
t.integer :day_of_week          # Rails converts to integer
t.datetime :appointment_date    # Proper DateTime
t.string :start_time, limit: 5   # Only for "HH:MM" strings, never for times

# WRONG - misusing string for everything
t.string :day_of_week           # Should be integer!
t.string :appointment_date      # Should be datetime!
t.string :start_time           # Sometimes correct (HH:MM), sometimes wrong (full datetime)
```

#### Time/Date Fields
```ruby
# Use proper types for temporal data
t.date :birth_date              # Dates only
t.datetime :created_at         # DateTime with timestamp
t.time :start_time, precision: 0  # Time only (no timezone in Rails Time)

# If storing as string (only for HH:MM format), comment WHY
t.string :start_time, limit: 5  # "09:30" in HH:MM format only
```

#### Model Associations - Name Things Correctly
```ruby
# Model name matches table name, association name matches foreign key
class SpecialistSchedule < ApplicationRecord
  belongs_to :specialist              # table: specialists, foreign_key: specialist_id
  belongs_to :account                # table: accounts, foreign_key: account_id
end

# WRONG - mismatched names cause bugs
belongs_to :patient  # when the FK is account_id
```

#### Model File Naming
```ruby
# Singular ClassName per file
app/models/specialist_schedule.rb    # class SpecialistSchedule
app/models/treatment_request.rb      # class TreatmentRequest

# NEVER plural, NEVER camelCase
app/models/SpecialistSchedule.rb     # WRONG
app/models/specialistSchedules.rb    # WRONG
```

### 2. ROUTES & PATHS

#### Route Naming (Always use _path with keyword arguments)
```ruby
# CORRECT - keyword arguments, plural resource name
get diseases_path
get disease_path(id: disease.id)
post diseases_path, params: { disease: { name: "Test" } }
patch disease_path(id: disease.id), params: { disease: { name: "Updated" } }

# WRONG - positional arguments fail with locale-prefixed routes
get disease_path(disease.id)           # Breaks with /:locale
get disease_path(id: disease.id, locale: I18n.locale)  # Only if locale is in route
```

#### Route Format
```ruby
# Standard RESTful routes
resources :diseases
resources :medications

# Namespaced routes
namespace :specialist do
  resources :profiles
  resources :schedules
end

# Results in:
# specialist_profiles_path
# specialist_schedules_path
# disease_path(id: ...)
# medication_path(id: ...)
```

#### Route Path Names (SINGULAR for singleton resources, PLURAL for collections)
```ruby
# Collection routes - PLURAL
diseases_path          # GET /diseases
medications_path       # POST /medications

# Member routes - SINGULAR with :id
disease_path(id: disease.id)    # GET/PATCH/DELETE /diseases/:id

# Named routes with keywords
edit_disease_path(id: disease.id)
new_disease_path
```

class ModelName < ApplicationRecord
  # Table: model_names (plural)

  # FK: account_id, specialist_id (always UUID)

  validates :field, presence: true

### 9. CONTROLLER PATTERN (Reference)
```ruby
class Namespaced::ResourceController < BaseController
  before_action :set_resource, only: [:show, :edit, :update, :destroy]

  def index
    @resources = ModelName.all
  end

  def show
    # Uses @resource set by before_action
  end

  def create
    @resource = ModelName.new(resource_params)
    if @resource.save
      redirect_to resource_path(id: @resource.id), notice: "Success"
    else
      render :new, status: :unprocessable_entity
    end
  end

  def update
    if @resource.update(resource_params)
      redirect_to resource_path(id: @resource.id), notice: "Updated"
    else
      render :edit, status: :unprocessable_entity
    end
  end

  private

  def resource_params
    params.require(:resource_name).permit(:field1, :field2)
  end

  def set_resource
    @resource = ModelName.find(params[:id])
  end
end
```
