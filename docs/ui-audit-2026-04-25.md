## Issues Found & Fixed

### Issue #1: `darken()` on CSS Variables ⚠️ CRITICAL
**Status:** ✅ FIXED

**Problem:** SCSS `darken()` function cannot operate on CSS variables. Lines 130, 309 in `_dash_home.scss` used:
```scss
color: darken($color-warning, 10%);  // FAILS - $color-warning is a CSS variable
```

**Fix:** Replace with hardcoded values or CSS color functions.

**File:** `app/assets/stylesheets/pages/_dash_home.scss`

---

### Issue #2: Header Pattern Inconsistency 🔴 HIGH
**Status:** ✅ FIXED

**Problem:** Three different header patterns across modules:
1. Patient: `page-header` component
2. Specialist dashboard: `dash-home__header`
3. Patient detail (specialist view): `dash-header`

**Fix:** Standardized on `page-header` component for ALL pages.

**Files Changed:**
- `app/views/specialist/dashboard/index.html.erb` - Changed from `dash-home__header` to `page-header`
- `app/views/specialist/patients/show.html.erb` - Changed from `dash-header` to `page-header`

**Verification:**
```bash
mise exec -- bundle exec rspec spec/requests/specialist/dashboard_spec.rb
mise exec -- bundle exec rspec spec/requests/specialist/patients_spec.rb
```

---

### Issue #3: Button Overload in Patient Detail Header 🔴 HIGH
**Status:** ✅ FIXED

**Problem:** Patient detail header had 5 buttons - too many:
1. Generate Report
2. Export FHIR
3. Import FHIR
4. Message
5. Back

**Fix:** Grouped Export/Import under a single "Data" dropdown, keeping primary actions clear.

**File:** `app/views/specialist/patients/show.html.erb`

---

### Issue #4: Form Pattern Inconsistency ⚠️ MEDIUM
**Status:** ✅ FIXED

**Problem:** Patient treatment request form uses two-column layout while specialist forms use single-column.

**Fix:** Standardized on two-column `dash-form` pattern for all forms.

**Files Changed:**
- `app/views/specialist/schedules/new.html.erb` - Updated to use two-column form pattern
- `app/views/specialist/schedules/edit.html.erb` - Updated to use two-column form pattern
- `app/views/specialist/notes/new.html.erb` - Already using correct pattern

---

### Issue #5: Copywriting Issues ⚠️ MEDIUM
**Status:** ✅ FIXED

**Problem:** Generic button labels that don't clearly communicate action.

**Changes:**
| Location | Before | After |
|----------|--------|-------|
| Patient detail "Generate Report" | "Generate Report" | "Download PDF Report" (with tooltip) |
| Specialist treatment requests tab | "My Prescriptions" | "Prescriptions Sent" |
| Patient treatment new button | ".button.new" | "Request Treatment" |

**Files Changed:**
- `config/locales/en/views.en.yml` - Updated translations

---

### Issue #6: Spacing Inconsistency (Hybrid Approach) 🟡 LOW
**Status:** Acknowledged - Acceptable for now

**Problem:** Mix of semantic SCSS variables (`$space-md`) and utility classes (`p-4`, `gap-3`).

**Decision:** Acceptable hybrid approach. Both are well-defined. No urgent fix needed.

## Components Standardized

### Page Header Component
```erb
<header class="page-header">
  <div class="page-header__left">
    <h1 class="page-header__title">
      <i class="ri-icon"></i>
      Page Title
    </h1>
    <%= render "shared/breadcrumbs" %>
  </div>
  <div class="page-header__right">
    <!-- Primary actions -->
    <%= link_to action_path, class: "dash-button dash-button--new" do %>
      <i class="ri-add-line"></i>
      Action
    <% end %>
    <%= link_to back_path, class: "dash-button dash-button--back" do %>
      <i class="ri-arrow-left-line"></i>
    <% end %>
  </div>
</header>
```

### Card Component Pattern
```erb
<div class="dash-group">
  <header class="dash-group__header">
    <h2 class="dash-group__title">
      <i class="ri-icon dash-group__title__icon"></i>
      Section Title
    </h2>
    <div class="dash-group__actions">
      <!-- Secondary actions -->
    </div>
  </header>
  <div class="dash-group__content">
    <!-- Content -->
  </div>
</div>
```

### Form Component Pattern (Two-column)
```erb
<div class="dash-form">
  <div class="dash-form__container">
    <div class="dash-form__group">
      <div class="dash-form__group__container">
        <div class="dash-form__group__left">
          <div class="dash-form__group__title">Field Label</div>
          <p class="dash-form__group__description">Helper text</p>
        </div>
        <div class="dash-form__group__right">
          <%= form.text_field :field, class: "dash-form__input" %>
        </div>
      </div>
      <%= render DashFormErrorComponent.new(model: @object, field: :field) %>
    </div>
  </div>
</div>
```

## Button Hierarchy Standard

| Variant | Usage | Visual |
|---------|-------|--------|
| `--new` | Primary action (submit, create) | Teal background |
| `--blue` | Secondary important (message) | Blue background |
| `--gray` | Tertiary (export, import, report) | Gray background |
| `--delete` | Destructive action | Red outline or gray with red icon |
| `--back` | Navigation only | Transparent with arrow |
| `--small` | Size modifier for tables/lists | Smaller padding |

**Rule:** Maximum 3 prominent buttons per header. Secondary actions in dropdown or section footers.
